\section{Database Schema}
Aetron separates high-frequency workout telemetry from relational profile and sync-queue state across two complementary local databases~\cite{isar2024database,sqflite2024}:
\begin{enumerate}
    \item \textbf{Isar NoSQL Store (\texttt{LocalDB}):} Persists three collections---\texttt{LocalWorkout} (Table~\ref{tab:isar_local_workout}), \texttt{LocalGPSPoint}, and \texttt{LocalStepInterval} (Table~\ref{tab:isar_local_points_steps})---with \texttt{relaxedDurability: false}. Every 5 seconds after meaningful workout progress (and on manual pause), an incremental crash-recovery checkpoint is written with \texttt{recording\_checkpoint: true} inside \texttt{routeMatchMetricsJson}. Checkpoints never upload as completed sessions and remain available for explicit user recovery or discard after unexpected OS termination. Crucially, sign-out and account switching preserve local records on disk while enforcing owner checks across repository reads, writes, deletes, and uploads.
    \item \textbf{SQLite Profile \& Sync Queue (\texttt{DatabaseHelper}, DB version~6):} Maintains \texttt{user\_profile} (body weight, height, date of birth, gender, avatar URL) and \texttt{pending\_workout\_sync\_operations} (\texttt{operation\_key}, \texttt{user\_id}, \texttt{session\_id}, payload metadata) so deferred offline uploads retry safely after connectivity restoration.
\end{enumerate}

\section{Cross-Platform Environment Classification and IOD}
\label{sec:environment_classifier_design}

\subsection{Probabilistic \texorpdfstring{\texttt{EnvironmentClassifier}}{EnvironmentClassifier} with Path Straightness and Causal HMM}
Replacing the pre-thesis classifier's ad-hoc weighted linear scores ($0.45/0.30/0.15/0.10$)~\cite{aetron2026prethesis}, Aetron's core \path{EnvironmentClassifier} (\path{lib/core/services/environment_detector.dart}) maintains a causal rolling window of $3$--$10$ GPS fixes alongside incoming pedometer step deltas and executes four scientifically grounded stages:
\begin{enumerate}
    \item \textbf{Continuous Sigmoid GNSS Likelihoods:} Rather than brittle step functions, horizontal accuracy $\bar{\sigma}_{\text{acc}}$, net displacement $d_{\text{net}}$, and speed $\bar{v}$ are transformed into smooth likelihoods $p_{\text{acc}}^{\text{Out}}$, $p_{\text{disp}}^{\text{Out}}$, and $p_{\text{speed}}^{\text{Out}}$ following Bui et al.~\cite{bui2020gpsiod} and DeepIOD~\cite{dastagir2024deepiod}.
    \item \textbf{Benhamou Path Straightness Index ($S$):} Evaluating tortuosity via~\cite{benhamou2004tortuosity}:
    \begin{equation}
        S = \frac{d_{\text{net}}}{\max(d_{\text{path}}, 1.0)} \in [0, 1], \qquad p_{\text{straight}}^{\text{Out}} = \sigma\bigl(5.0\,(S - 0.35)\bigr),
        \label{eq:benhamou_s}
    \end{equation}
    separates linear outdoor trajectories ($S \to 1$) from indoor multipath star patterns ($S \to 0$).
    \item \textbf{Pedometer--GPS Discordance and iPhone Blackout Gate:} Multi-cue fusion combines $(0.45, 0.25, 0.15, 0.15)$ likelihood weights, adding strong indoor emission ($0.05$, weight $0.45$) whenever poor GPS accuracy, small displacement, and increasing steps coincide. Furthermore, because \texttt{CoreLocation} on iPhones often ceases emitting fixes inside steel gyms before $3$ samples arrive, observing $\ge 8$\,s of GPS silence alongside $\ge 10$ verified steps emits an immediate indoor fallback state.
    \item \textbf{Causal 2-State HMM Forward Filter:} Following Zhu et al.~\cite{zhu2019fast}, emission probability $b_t(\text{Out}) \in [0.02, 0.98]$ updates the posterior state belief $\alpha_{\text{Out}}(t)$ with self-transition retention $p_{\text{stay}} = 0.90$ under strong cues ($|b_t - 0.5| \ge 0.30$) and $0.97$ otherwise.
\end{enumerate}

\subsection{Android Model~C-Mobile and iOS-First Light-Free IOD (\texorpdfstring{\texttt{IodCompositeClassifier}}{IodCompositeClassifier})}
Beyond the core tracker hint, \texttt{IodCompositeClassifier} dispatches multi-sensor context windows (\texttt{IodSensorSnapshot}) according to verified OS sensor hardware:
\begin{itemize}
    \item \textbf{Android Path (4-Channel Model~C-Mobile \& Adaptive Transition Engine):} Devices exposing an ambient photodiode run \path{DeepIodNeuralClassifier}, a pure-Dart 2D Depthwise-Separable CNN over $\mathbf{X} \in \mathbb{R}^{4 \times W} = [\text{Light}, \text{Mag}, \text{Acc}, \text{Daytime}]$ ($54.0$\,KB folded weights, $<0.8$\,ms inference)~\cite{dastagir2024deepiod}, fused optionally with Yoo's $30$--$40$\,dB-Hz GNSS $C/N_0$ transition detector~\cite{yoo2025seamless} and stabilized inside \texttt{IndoorOutdoorTransitionEngine} (Algorithm~\ref{alg:transition_engine}).
    \item \textbf{iOS-First Light-Free Path (\texttt{IosMultiSensorIodClassifier}):} Because Apple iOS blocks ambient light, raw $C/N_0$, and cellular radio APIs, Aetron executes \texttt{IosMultiSensorIodClassifier} inside \path{lib/features/iod/domain/services/}:
    (1)~extracts 10 distributional MagIO~\cite{ashraf2018magio} features (mean, SD, min, max, range, median, IQR, skewness, kurtosis, mean $|\Delta \|\mathbf{m}\||$) over a causal $10$\,s magnetometer buffer; (2)~appends 3 linear acceleration features~\cite{kelishomi2019activities} (mean, SD, peak-to-peak excursion) plus astronomical daytime into a frozen 14-feature pure-Dart 2-layer MLP ($<4$\,KB, $<50$\,$\mu$s); (3)~fuses runtime \texttt{CoreLocation} accuracy/blackout likelihoods~\cite{bui2020gpsiod} and \texttt{CMAltimeter} $10$\,s pressure deltas ($|\Delta P_{10\text{s}}| \ge 0.35$\,hPa~\cite{feriol2020review}); and (4)~filters predictions via Zhu et al.'s causal 2-state HMM ($A_{ss} = 0.90$)~\cite{zhu2019fast}.
\end{itemize}

Crucially, because external benchmarks reveal locomotion confounding on HAR-PMD and modest doorway transition recall (Chapter~\ref{ch:evaluation}), all IOD subsystems hardcode \texttt{isObservationalOnly = true}. In \path{WorkoutEnvironmentController.resolveIodAdvice}, predictions older than $2$\,s are expired and advisory hints can never override active distance tracking or contradict resolved GNSS/step state.

\begin{algorithm}[htbp]
\KwIn{Sensor Snapshot $\mathbf{s}_t$, Prior State $S_{t-1}$, Hysteresis $(\theta_{\text{high}}=0.65, \theta_{\text{low}}=0.35)$, Dwell Epochs $N_{\text{dwell}}=5$}
\KwOut{Committed Observational State $S_t \in \{\text{Indoor}, \text{Outdoor}\}$, Uncertainty Flag $U_t$}
$P_t \leftarrow \text{ModelC\_Mobile}(\mathbf{s}_t)$\;
$U_t \leftarrow (0.40 \le P_t \le 0.60)$\;
\eIf{$S_{t-1} == \text{Indoor}$}{
    $C_t \leftarrow (P_t \ge \theta_{\text{high}})\; ?\; \text{Outdoor} : \text{Indoor}$\;
}{
    $C_t \leftarrow (P_t \le \theta_{\text{low}})\; ?\; \text{Indoor} : \text{Outdoor}$\;
}
\eIf{$C_t \ne S_{t-1}$}{
    $\text{PendingDwell}_t \leftarrow (C_t == \text{PendingState}_{t-1})\; ?\; \text{PendingDwell}_{t-1}+1 : 1$\;
    $\text{PendingState}_t \leftarrow C_t$\;
    \eIf{$\text{PendingDwell}_t \ge N_{\text{dwell}}$}{
        $S_t \leftarrow C_t$; $\text{PendingState}_t \leftarrow \text{None}$; $\text{EmitHandover}(S_{t-1} \to S_t)$\;
    }{
        $S_t \leftarrow S_{t-1}$\;
    }
}{
    $S_t \leftarrow S_{t-1}$; $\text{PendingState}_t \leftarrow \text{None}$; $\text{PendingDwell}_t \leftarrow 0$\;
}
\Return{$(S_t, U_t)$}\;
\caption{Adaptive Transition Engine Debouncing (\texttt{IndoorOutdoorTransitionEngine})}
\label{alg:transition_engine}
\end{algorithm}

Each incoming fix passes four gating stages in \texttt{WorkoutTrackingEngine} (Table~\ref{tab:gps_validation_params}) alongside Phase~1 kinematic preprocessing~\cite{zheng2015trajectory,li2025trajectory}, before entering \texttt{ExtendedKalmanFilter} on a local Equirectangular East--North tangent plane:
\begin{align}
    p_x &= R_{\text{earth}} (\lambda - \lambda_0) \cos\!\left(\frac{\phi_0\pi}{180}\right)\frac{\pi}{180}, \qquad
    p_y = R_{\text{earth}} (\phi - \phi_0)\frac{\pi}{180}.
\end{align}
The EKF resolves the pre-thesis Fixed-Alpha freeze failure via: (1)~heading phase normalization with modality Doppler deadbands ($0.8/1.2/1.8$\,m/s); (2)~flat \texttt{Float64List} Joseph-form covariance updates (Eq.~\ref{eq:joseph_form}) with Cauchy--Schwarz clamping ($|P_{EN}| \le 0.99\sqrt{P_{EE}P_{NN}}$); (3)~Phase~2 2-DOF Mahalanobis NIS gating ($\gamma_1 = 5.991$, $\gamma_2 = 13.816$, consecutive re-anchoring $N_{\text{reanchor}}=4$) and centripetal turn-rate scaling ($\mu_\theta = \min(\mu_{\max}, 1 + 0.8(\dot{\psi}_k/\omega_{\text{th}})^2)$)~\cite{groves2013principles,rongli2003survey,sukhenko2025gnss}; (4)~stationary ZUPT clamping when $v < 0.3$\,m/s for $\ge 3$\,s; and (5)~post-session \texttt{GpsDbscanService} T-DBSCAN dwell consolidation ($v_k \le 1.0$\,m/s, $\varepsilon = 6.5$\,m, $\mathrm{MinPts} \ge 4$, duration $\ge 10$\,s)~\cite{ester1996dbscan}. Debug overrides and research flags reside cleanly in \path{lib/core/constants/debug_config.dart} (Table~\ref{tab:gps_validation_params}).

\subsection{Display-Only Outage Reconstruction, Sanitization, and Compression}
To render smooth visual summaries without fabricating unmeasured mileage, \texttt{WorkoutSessionFinalizer} bridges short $2.0$--$15.0$\,s gaps in display geometry only (via Fritsch--Carlson Monotone PCHIP or Linear Chord), never adding synthetic vertices to saved distance or server raw audits, while \path{route_display_sanitizer.dart} removes residual sharp display artifacts on recap cards. \section{Indoor Step Tracking and Cadence Pipeline}
\label{sec:indoor_pipeline_design}
Indoors or during GNSS blackouts, \texttt{StepTrackingService} anchors hardware pedometer counts across device reboots ($N_{\text{steps}} = C_{\text{current}} - C_{\text{baseline}}$), while Aetron's pure-Dart inertial stack prevents idle false steps and stabilizes cadence:
\begin{enumerate}
    \item \textbf{Causal Accelerometry Detectors:} \texttt{OxfordStepDetector}~\cite{salvi2018oxford} (100\,Hz Gaussian smoothing, Welford online variance, $200$\,ms refractory confirmation) handles walking, while \texttt{XuRunningStepDetector}~\cite{xu2022step} (50\,Hz Hamming LPF, 256-pt real DFT dominant frequency, adaptive window peaks) handles running.
    \item \textbf{Skog MV-GLRT ZUPT \& Brajdic--Harle \texttt{StepMotionGate}:} Evaluating Eq.~\ref{eq:mv_glrt_lit} over $1.0$\,s sliding windows rejects isolated impulsive shocks ($\gamma_{\text{MV}} = 0.36\text{ (m/s}^2)^2$ walk; $0.64\text{ (m/s}^2)^2$ run)~\cite{skog2010zupt}. Downstream, \texttt{StepMotionGate} (\path{lib/features/workout/domain/services/step_motion_gate.dart}) buffers unconfirmed steps until $N_{\text{bout}} = 5$ consecutive steps occur within $[0.65, 4.5]$\,Hz (max gap $2.2$\,s), expires stale bouts after $3.5$\,s, and purges buffered impulses when outdoor GNSS proves stationary position past a $3.5$\,s onset grace window---eliminating stationary step inflation when users stand still checking their screen~\cite{brajdic2013walk}.
    \item \textbf{6-Second Cadence Window \& Renaudin Adaptive Stride Length:} \texttt{CadenceCalculatorService} computes live cadence over a $6.0$\,s sliding FIFO buffer with a $4.0$\,s silence timeout, capped at $270$\,spm via $N_{\text{window}}\times 60 / 6.0$. For indoor distance estimation, \texttt{ResearchStepLengthFallback} applies LOSO-validated Renaudin Eq.~\ref{eq:renaudin_lit} coefficients---$(a, b, c) = (0.1328, 0.0217, 0.2755)$ walking and $(0.3211, 0.7253, -1.6810)$ running~\cite{renaudin2012step}---clamping to validated training bounds before invoking deterministic profile height/gender defaults (Listing~\ref{lst:stride_length})~\cite{taborri2016gait}.
\end{enumerate}

\begin{lstlisting}[caption={Adaptive stride-length dispatch with height-based fallback in \texttt{record\_providers.dart}.},label={lst:stride_length}]
double computeStrideLength({
  required String activityType, double? heightCm, String? gender,
}) {
  final research = ResearchStepLengthFallback.estimateMeters(
    activityType: activityType, heightCm: heightCm,
  );
  if (research != null) return research;
  if (heightCm == null || !heightCm.isFinite || heightCm <= 0) {
    return _defaultStrideLength(activityType, gender);
  }
  final isRunning = activityType.toLowerCase().contains('run');
  final female = _normalizeGender(gender) == 'female';
  final factor = isRunning ? (female ? 0.62 : 0.67) : (female ? 0.40 : 0.43);
  return (heightCm * factor / 100).clamp(0.50, 1.50);
}
\end{lstlisting}

\section{Calorie Estimation (2024 Adult Compendium)}
Upgrading the pre-thesis distance-multiplier heuristic ($W \times D_{\text{km}} \times k \times g$)~\cite{aetron2026prethesis}, both \path{UserProfile.calculateCalories} (Dart) and \path{compendium_met.ts} (Supabase Deno edge worker) implement Eq.~\ref{eq:compendium_2024} using exact 5-digit speed-banded lookup tables from the \textbf{2024 Adult Compendium of Physical Activities}~\cite{herrmann2024compendium}: walking (\texttt{17151}--\texttt{17255}, general fallback \texttt{17255} at $4.0$\,MET), running (\texttt{12028}--\texttt{12145}, self-selected \texttt{12145} at $10.5$\,MET), and cycling (\texttt{01010}--\texttt{01060}, general \texttt{01014} at $7.0$\,MET) via $v_{\text{mph}} = v_{\text{km/h}}/1.609344$. Speed values falling in unmapped gaps never interpolate heuristic METs, and ambulatory sessions with zero verified displacement return strictly $0$\,kcal. Non-distance indoor activities (gym, yoga) retain legacy duration MET estimation.

\section{Synchronisation Strategy}
On session completion, \texttt{WorkoutRepositoryImpl} persists pending raw telemetry and writes the finalized \texttt{LocalWorkout} to Isar (\texttt{isSynced = false}) prior to network transmission. Failed uploads queue in SQLite \texttt{pending\_workout\_sync\_operations}; remote history pulls paginate by stable ID, check active account ownership, protect unsynced local edits, and acknowledge sync via full-snapshot value comparison (\texttt{sameSnapshot}) including UTC instants and serialized splits/routes.

\section{Backend Processing Pipeline}
Beyond proof-of-concept endpoints established at the pre-thesis stage (\texttt{workouts-start}, \texttt{gps-track}, \texttt{workouts-end}), Supabase Deno edge workers enforce canonical server metrics:
\begin{itemize}
    \item \texttt{deterministic-finalize-worker}: Recomputes canonical distance, moving speed, 2024 Compendium calories (\texttt{METRICS\_VERSION = 2}), and per-segment \texttt{workout\_segment\_audits} from uploaded \texttt{raw\_gps\_points} and \texttt{raw\_step\_intervals}, retaining unverified client-mixed claims in a separate audit archive.
    \item \texttt{route-correction-worker}: Implements the chunked HMM map-matching contract~\cite{newson2009hidden} while returning \texttt{routeMatchingAvailable() = false} honestly whenever no live OSRM road-graph provider is attached, preventing fake geometry promotion.
\end{itemize}

\section{Cross-Screen Data Consistency}
All five shell tabs (\texttt{MainShell}: Home, Activity/Record, History/Calendar, Analytics/Stats, Profile) along with Summary and Details screens consume workout streams and entities exclusively through \texttt{WorkoutRepository}. Lap splits, filtered routes, moving duration, steps, and calories are saved once at finalization and rendered identically without view-local recalculation.
